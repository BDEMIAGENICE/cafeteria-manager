Déployer les pages publiques

La branche main contient une page sans connexion pour les étudiants, avec deux onglets : les jours d'ouverture des 4 prochaines semaines et le stock du service, aussi affiché sur l'écran devant le comptoir. Elle est construite avec le site : sur Vercel, il suffit de récupérer main, d'ajouter deux fonctions SQL et de redéployer. Comptez 5 minutes.

Jours d'ouverture et stock https://<votre-site>.vercel.app/cafet/
Directement sur un onglet …/cafet/#horaires · …/cafet/#stock

Avant de commencer

  • Un accès à l'éditeur SQL du projet Supabase utilisé par le site.
  • Un accès au projet Vercel du site.
  • Une copie locale du dépôt, avec Git.
  • Dans Vercel, VITE_SUPABASE_URL et VITE_SUPABASE_PUBLISHABLE_KEY doivent déjà exister (Settings → Environment Variables), puisque le site en a besoin. La page publique réutilise ces deux valeurs pour la page : il n'y a aucune clé à copier à la main.

Les trois étapes

  1. 1

    Créer les fonctions dans Supabase

    Éditeur SQL · 2 minutes

    Dans Supabase, ouvrez SQL Editor → New query, collez le premier script et cliquez sur Run. Supabase doit répondre « Success. No rows returned ». Faites de même avec le second.

    Script 1 : le stock du service

    supabase/migrations/20261109000000_public_stock.sql 
    -- Public stock page (public-stock/): what the café has, readable without signing in.
-- The products table stays staff-only. This function is the only way in for visitors,
-- and it returns only what the page shows: never the purchase cost, the weekly usage
-- or ids.
--
--   status: 'out' when nothing is left, 'low' at or under the minimum level, else 'ok'
--   price:  the selling price, null when none is set

create or replace function public.public_stock()
returns table (name text, category text, quantity numeric, status text, price numeric)
language sql
stable
security definer
set search_path = ''
as $$
  select
    p.name,
    nullif(trim(p.category), ''),
    p.current,
    case
      when p.current <= 0 then 'out'
      when p.current <= p.min_level then 'low'
      else 'ok'
    end,
    nullif(p.price, 0)
  from public.products p
  order by nullif(trim(p.category), '') nulls last, p.name
$$;

revoke all on function public.public_stock() from public;
grant execute on function public.public_stock() to anon, authenticated;

    Script 2 : les jours d'ouverture, semaine par semaine

    supabase/migrations/20261110100000_service_weeks.sql 
    -- A plan for each week: which days the café opens can change from one week to the next
-- (this week Tuesday and Thursday, next week Monday, Wednesday and Friday, the one after
-- every day).
--
--   service_weeks   one row per planned week, identified by its Monday. `days` lists the
--                   open days of that week: [{ "weekday": 2, "time_label": "12:15–13:30",
--                   "needed": 2 }, …] (weekday 1 = Monday … 7 = Sunday). An empty list is a
--                   week that is shut.
--
-- The service of a date is, in this order: its exception in service_days if it has one,
-- else its week's plan if the week has one, else its weekday's usual hours in
-- opening_hours. A week with no row follows the usual hours, so nothing changes until an
-- admin plans a week, and weeks far ahead keep working without being planned.

create table if not exists public.service_weeks (
  week_start date  primary key check (extract(isodow from week_start) = 1),
  days       jsonb not null default '[]'::jsonb check (jsonb_typeof(days) = 'array')
);

-- Same access as the other schedule tables: staff read, admins edit, nothing for visitors
-- (they go through public_opening() below).
alter table public.service_weeks enable row level security;
revoke all on public.service_weeks from anon;

drop policy if exists staff_read on public.service_weeks;
drop policy if exists admin_write on public.service_weeks;
create policy staff_read on public.service_weeks for select to authenticated using (public.is_staff());
create policy admin_write on public.service_weeks for all to authenticated
  using (public.is_admin()) with check (public.is_admin());

-- Public opening page (public-opening/): follows the same rule as the app.
--
--   open:       whether the café opens that day
--   time_label: its hours, null when closed
--   special:    the day differs from what its week plans (closed on a planned day, open on
--               an unplanned one, or other hours), because an admin set an exception for
--               that date. A week's own plan is not "special": it is the schedule.
--
-- Returns the coming `days` days (1 to 90, from today in Paris). Nothing about staff or
-- sign-ups leaves the database.
create or replace function public.public_opening(days int default 28)
returns table (date date, open boolean, time_label text, special boolean)
language sql
stable
security definer
set search_path = ''
as $$
  with span as (
    select ((now() at time zone 'Europe/Paris')::date + i) as day
    from generate_series(0, least(greatest(coalesce(days, 28), 1), 90) - 1) as i
  ),
  planned as (
    -- the hours the week gives that day: its own plan if it has one, else the usual hours
    select
      span.day,
      case
        when sw.week_start is not null then (
          select p.time_label
          from jsonb_to_recordset(sw.days) as p(weekday int, time_label text)
          where p.weekday = extract(isodow from span.day)::int
          limit 1
        )
        else oh.time_label
      end as label
    from span
    left join public.service_weeks sw
      on sw.week_start = span.day - (extract(isodow from span.day)::int - 1)
    left join public.opening_hours oh
      on oh.weekday = extract(isodow from span.day)
  )
  select
    planned.day,
    hours.label is not null,
    hours.label,
    hours.label is distinct from planned.label
  from planned
  left join public.service_days sd on sd.date = planned.day
  cross join lateral (
    select case when sd.closed then null else coalesce(sd.time_label, planned.label) end as label
  ) as hours
  order by planned.day
$$;

revoke all on function public.public_opening(int) from public;
grant execute on function public.public_opening(int) to anon, authenticated;

    Pour vérifier, lancez ces requêtes : la première liste les produits avec leur état, la seconde les 7 prochains jours.

    Vérification 
    select * from public_stock();
select * from public_opening(7);

    Les tables restent réservées à l'équipe. Ces deux fonctions sont la seule porte d'entrée pour les visiteurs. public_stock renvoie le nom, la catégorie, la quantité, l'état et le prix de vente, jamais le coût d'achat ni la consommation. public_opening renvoie les dates et les horaires, rien sur l'équipe ni sur les inscriptions.

  2. 2

    Récupérer la branche main

    Terminal · 1 minute

    Récupérez main dans la branche que Vercel déploie (Vercel → Settings → Git → Production Branch), puis poussez-la.

    Vercel déploie main

    bash 
    git checkout main
git pull https://github.com/Tonoplas909/cafeteria-manager.git main
git push

    Vercel déploie deploy

    bash 
    git checkout deploy
git pull https://github.com/Tonoplas909/cafeteria-manager.git main
git push

    Sur deploy, Git crée un commit de fusion : acceptez le message proposé. La fusion a été testée et ne crée aucun conflit.

    Pas de fonction Supabase à redéployer. Ce changement ne touche ni calendar-sync ni staff-admin. En particulier, ne redéployez pas staff-admin depuis main : la version de la branche deploy lit l'adresse du site dans le secret SITE_URL, celle de main n'autorise que l'ancienne adresse GitHub Pages.

  3. 3

    Déployer sur Vercel

    Automatique · 1 à 2 minutes

    Le git push de l'étape 2 lance le déploiement tout seul. Les réglages Vercel ne changent pas : commande de build npm run build, dossier de sortie dist.

    Pendant le build, la page est copiée dans dist/cafet/ avec les valeurs VITE_SUPABASE_… du projet Vercel. Pour relancer un déploiement à la main : Vercel → Deployments → Redeploy, ou en ligne de commande :

    bash 
    npx vercel --prod

Vérifier

  • https://<votre-site>/cafet/ s'ouvre sans demander de connexion, avec deux onglets : « Jours d'ouverture » et « Stock ».
  • L'onglet Stock affiche les produits par catégorie. Un encadré indique que ce n'est pas le stock en temps réel : l'équipe le met à jour à la main au début de chaque service.
  • Changez un stock dans l'app : la page affiche la nouvelle quantité en moins de 30 secondes, sans être rechargée (c'est ce que fait l'équipe en début de service).
  • L'onglet Jours d'ouverture affiche l'état du jour (compte à rebours avant l'ouverture, « La cafet est ouverte actuellement » en vert pendant le service, « Service terminé pour aujourd'hui », ou « Fermé aujourd'hui » avec la prochaine ouverture) et les 4 prochaines semaines.
  • Planifiez une semaine dans l'app (Planning → Planifier la semaine, par exemple mardi et jeudi seulement) : l'onglet Jours d'ouverture n'affiche que ces jours ouverts pour cette semaine.
  • Fermez un jour dans l'app (Planning → Modifier ce jour) : il apparaît en « Fermeture exceptionnelle » dans l'onglet Jours d'ouverture.
  • Les anciennes adresses …/stock/ et …/horaires/ redirigent vers le bon onglet.
  • Le reste du site fonctionne comme avant, connexion comprise.

L'écran devant la cafet

Ouvrez https://<votre-site>/cafet/?ecran dans le navigateur de l'écran et passez en plein écran (F11). L'écran n'affiche que le stock, sans onglets. Les textes sont plus grands, le curseur est masqué, l'écran ne se met pas en veille quand le navigateur le permet, et la liste défile doucement si elle dépasse la hauteur de l'écran. La page se met à jour toute seule toutes les 30 secondes et garde le dernier stock affiché si le réseau coupe.

Dépannage

Ce que vous voyezCauseQue faire
« Page pas encore configurée » Les variables VITE_SUPABASE_… manquaient au moment du build. Ajoutez-les dans Vercel pour l'environnement Production, puis Redeploy.
« Le stock ne peut pas être affiché pour le moment » La fonction public_stock n'existe pas dans le projet Supabase du site. Refaites l'étape 1 (script 1) dans le bon projet, puis vérifiez avec select * from public_stock();.
« Les horaires ne peuvent pas être affichés pour le moment » La fonction public_opening n'existe pas dans le projet Supabase du site. Refaites l'étape 1 (script 2), puis vérifiez avec select * from public_opening(7);.
404 sur /cafet/ Le déploiement a été fait sur un commit qui n'a pas encore la page. Vérifiez dans Vercel → Deployments que le commit déployé contient le dossier public-cafet/.
Le stock ne baisse pas pendant le service Comportement normal : le stock est saisi une fois, en début de service. Rien à faire. La page le précise aux étudiants.
La page est dans le dossier public-cafet/ du dépôt. Son README.md explique aussi comment l'héberger seule, en dehors du site.
